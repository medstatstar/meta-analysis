## 2. 四个必须先知道的静默失效模式

四条有**同一个家族特征：接口不报错，只是安静地少做事**。

| 病灶 | 症状 | 为何隐蔽 |
|---|---|---|
| 写死解释器路径（`tool_mapping_meta.json` ×2、`RSCRIPT_BIN`） | A1 探针「无返回」、A2 合并 0 篇 | `except Exception` 吞掉 → `status:error` → 兜底读空目录 |
| 元组解包元数不对称（A4 下载路径） | 首轮全篇「待补传 PDF」，**重跑却正常** | 重跑走缓存分支（那条是 6 元组）→ 用户误判成 OA 覆盖不足 |
| 缺 PyMuPDF | A4 抽取 `extract_fail` | `pdf_extractor` 可导入（`pdfplumber` 在）→ 不走 `is None` 早返回 |
| **旧会话数据（本轮新识别）** | 菜单**正常渲染**，但渲染的是**改造前的语义** | 渲染器只做投影，不做版本校验；旧字段缺位时取 `None` 而非报错 |

**可复用教训 1**：**改了返回契约（元组加长、字段新增）后，必须 `grep` 全部调用点逐一核对解包元数。**
`_a4_extract_pdf` 这次是 3 个调用点改了 2 个，漏的那个恰好在最关键路径上。

**可复用教训 2**：**菜单贴给用户前，先验会话是不是当前契约写的**（见 §8 陷阱 I）。

## 4. 类型确认链路（D17-A）

```
ct-literature classify_record()      ← 单一真源，不新写判定
        ↓ 规则预填
A3 导出表「文献类型确认」列            ← 人工确认 / 改判 / 留空
        ↓ 回传 parse_screening_xlsx
决策行 doc_type（一等字段）+ 审计字段
        ↓ 只读
A4 per_doc.doc_type  ← 抽取层探测降为 doc_type_detected，仅不一致时提示
```

**回传三条口径**

| 情形 | 结果 |
|---|---|
| 单元格非空 | 权威值，`doc_type_source="human"`；与预填不同 → 记 `doc_type_changed` + 留 `doc_type_rule` 对照（**「改判几篇」可审计**） |
| 留空 | 未确认 → 沿用规则预填，`doc_type_source="rule"`（不拦流程，计数可见） |
| 取值非法 | **报错不前进**，并指出具体哪一行 |

**保留的两处类型判断——都不越界**

| 位置 | 为何留 |
|---|---|
| A3 `is_likely_review()` review-guard（预填 `rule_decision`） | 处于**人工确认之前**，是预填建议，人工可改 |
| `a4_stream.review_note` / 工作台 `🔍 疑似综述` 徽标 | 纯**提示**，不做任何排除 |

> **澄清一个易误判点**：`a4_stream` 里的 `gate="relevance_skip"`（`block_a.py:1602`）触发条件是
> `decision_of(sc) == DECISION_EXCLUDE` —— 它**消费 A3 的裁决**，**不是**在 A4 重新判类型。
> 会话数据里的 `reason` 文案「review-guard 默认排除：命中综述特征…」是 **A3 侧写下的默认理由**，被 A4 原样带出。
> 看到这句话不要误判为「A4 又在判类型」。

## 5. CCM 怎么调用

### 5.1 两个调用面

**生产用法（推荐）：用户不敲命令。** 用户说 `启动上下文菜单` / `继续` / `全流程`，或直接回一个编号（`1` / `批准` / `回退 ③`）；
agent 读 `SKILL.md` 的 CCM 条目 → 跑渲染器 → 把菜单贴回 → 用户回编号后再 `--apply`。
选项 ≤3 个走点选卡片，≥4 个贴编号文本。

**终端直连（调试 / 验收）**

```bash
PY=C:/Tools/Anaconda3/python.exe          # 绝对路径，别依赖 PATH
cd C:/Users/Wintone/.workbuddy/skills/meta-analysis

$PY scripts/flow_menu.py status [--session P] [--lang zh|en] [--json]
$PY scripts/flow_menu.py menu   [--session P] [--lang zh|en] [--json]   # 可直接贴给用户
$PY scripts/flow_menu.py nodes  [--lang zh|en]                          # 12 节点总表
$PY scripts/flow_menu.py decide [--session P] --option 1 [--set k=v ... | --revision '<json>'] [--apply]
$PY scripts/flow_menu.py rewind [--session P] --target A2.literature_search [--apply]
```

- `--session` 省略 → 取 `adapters/workbench/runs/` 下 `updated_at` **最新**的会话（**注意：可能正是旧契约数据，见 §8 陷阱 I**）。
- `decide` / `rewind` **默认 dry-run，只校验不落盘**；`--apply` 才推进状态机。
- 退出码：`0` 成功 / `2` 用法或校验错误 / `3` 会话缺失不可读。
- 校验**一律走 `fullflow._validate_decision`**，本层不复述规则。
- **每次调用约 10 秒**（实测：`import fullflow` 占 **8.5s**，渲染本身 0.3s）→ 别在一个节点上连敲多条命令，一次 `--json` 拿够信息。
