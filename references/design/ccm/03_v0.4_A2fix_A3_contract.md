## 1. A2 修复记录（已完成 · 已验证）

### 1.1 问题

`adapters/tool_mapping_meta.json` 两条 `cmd[0]` 都写死 `C:/Anaconda3/python.exe`，本机不存在（实际 `C:/Tools/Anaconda3/python.exe`）。`_load_tool_mapping()` 只展开 `skill_dir`、不碰 `cmd`，于是：

```
FileNotFoundError → execute_tool_cards 的 except Exception 吞掉（coze_client.py）
→ status:"error" → _extract_studies 空 → _read_literature_dir 兜底读空
→ A2 检索静默 0 篇；A1 注册库查重静默"无返回"，界面上都看不到报错
```

### 1.2 修法（3 处，未触碰 CCM 任何设计）

| 文件 | 改动 |
|---|---|
| `adapters/tool_mapping_meta.json` | 两条 `cmd[0]` 改为占位符 `{python}`；`_comment` 补写"勿再写死绝对解释器路径，否则换机后子进程启动失败会被静默吞成空结果" |
| `adapters/coze_client.py` | 新增 `resolve_python_exe()`：**环境变量 → Anaconda base 候选 → `sys.executable` → PATH**，只接受**实际存在**的文件；`_load_tool_mapping()` 负责解析 `{python}` |
| `adapters/coze_client.py` | 新增 `import shutil` |

设计取向：**硬编码路径从"环境事实"降级为"候选之一"**。不再有第二处需要跟着换机一起改。

### 1.4 回归顺带发现的两件事（都影响 A2 菜单文案，需一并处理）

**发现 A · `--max` 是每源上限，不是合并上限。**
`ct_literature.py` 把 `max_results` 分别传给 openalex / europepmc / biorxiv / medrxiv（各源独立调用）。所以 `--max 5` 实得 **20 篇**（5 × 4 源，恰好无重复）。
→ A2 面板现在标"检索上限 = 5"**会误导**（用户以为只取 5 篇）。简化后的 A2 菜单应写 **"检索上限 5/源（合并 20）"**。

**发现 B · `--out-dir` 文件才是主路径，不是兜底。**
stdout 只输出 NDJSON 日志，`_parse_tool_output` 拿不到记录 → `_extract_studies(result)` **恒为 0**；数据全在 `.merged.json` 的 `works[]`。
→ 代码注释把 `_read_literature_dir` 写成"回退读取"、调用处写"# 真实 ct-literature：读 --out-dir 文件"，**命名与注释都把它当兜底**。这是维护陷阱：后人可能据此删掉"兜底分支"。建议改名/改注释为"主路径"。

**发现 C（未修，建议排期）**：`a1_registry_check` 的兜底文案 `"ct-registry 无返回（映射缺失？）"` 仍把"解释器坏了"与"注册库真没查到"混为一谈。解释器修好后这条文案不会主动触发，但探针层仍应区分 `status:error` 与"零命中"。

## 2. A3 = 纯文件交接（决策落地）

### 2.1 口径变化

| | v0.2 原设计 | v0.4（本轮定） |
|---|---|---|
| A3 对话形态 | Top-N 预览 + 边界项逐条裁决（N≤10 允许对话内改） | **不逐条**。唯一动作 = ⬇ 导出 → 改 → ⬆ 传回 |
| 边界项 | 对话内定夺 | 并入同一张导出表（预填规则裁决，用户只翻例外） |
| 文件交接 | `[2] 修订` 局部逃生门 | **默认且唯一路径** |
| 落点 | 改完 → 回 A3 再批 | 改完 → 上传 → **直接进 A4**（A4 🔴 自有人工闸） |

**收益**：A3 菜单塌缩到 5 个选项；"42 条逐条"彻底移出对话；与工作台行为**完全一致**（工作台本来就有 ⬇⬆ 通道）→ **A3 上的双端漂移风险归零**。

### 2.2 A3 对话菜单（最终形态）

```
③ 初筛 · 导出裁决表              〔软停 · 需你拍板〕
   去重 42 ｜ 规则纳入 14 / 规则剔除 28（非原创类型 3 · 主题无关 25）
   ⬇ 导出裁决表 screening_v3.xlsx → 改「裁决」「理由」两列 → ⬆ 传回，即接 ④ 数据提取
   [1] 导出裁决表     [2] 传回修改后的表（→ ④ A4 🔴）
   [3] 跳过本阶段     [4] 打回 / 回退     [5] 解释本节点
```

### 2.3 裁决表契约（导出）

| 列 | 可编辑 | 说明 |
|---|---|---|
| `#` | ✕ | 行号：供定位与回传对齐 |
| `title` | ✕ | 只读锚点 |
| `journal` / `year` / `authors` / `study_type` | ✕ | 裁决依据 |
| `doi` / `pmid` / `source` | ✕ | 匹配键 |
| **`rule_decision`** | ✕ | ct-literature 规则裁决（`prisma_included`） |
| **`rule_reason`** | ✕ | `non-original-type:review` / `topic-no-token` / 空 |
| **`decision`** | ✓ | `include` / `exclude` / `uncertain`；**预填 `rule_decision`** |
| **`reason`** | ✓ | 自由文本；`exclude` 时必填 |

> **预填不是省事，是防漂移。** 用户面对"已填好的表"时，改动量 = 真实分歧量；若留空白，用户实际在重做一遍规则判定 —— 规则跑了个空。

### 2.4 回传（导入）契约

**匹配键**：`doi` → 退化 `pmid` → 退化 `(# + title)`。行缺失 = 该篇维持原裁决（不视为删除）。

**校验（任一失败 → 不前进，报明确原因 + 保留用户文件）**

| 检查 | 失败文案 |
|---|---|
| 表头 8 个必需列齐全 | "缺少列 X" |
| `#` / `title` 能与导出快照对齐 | "行被删改，请用导出的原表" |
| `decision` ∈ {include, exclude, uncertain} | "第 N 行裁决值非法：xxx" |
| `exclude` 必须填 `reason` | "第 N 行剔除未填理由" |
| 不允许新增行（可删行） | "新增了 N 行，裁决表不接受新增" |

**应用语义**

1. 写 `human_decisions`（既有机制，A3 即审计）——一次 `action=revised` 批量记录
2. ~~人工把疑似综述翻为 `include` 的篇目 → 必须置 `_skip_page_screen=True`~~
   **【已被 D14 取代】** A4 的下载前类型门整体移除后，此豁免补丁失去存在意义，已随之删除（见 §2.6）。
3. 汇总回显后**直接进 A4**：`已应用 42 条（纳入 14 · 剔除 28 · 低置信 0）→ ④ 数据提取（🔴 红线）`
4. **不写** `pending_actions`（文件已回传，待办即清）

> **原第 2 条曾是硬约束**：`_a4_fetch_one` 的下载前类型门（`block_a.py:1216`）会对"人工翻纳入的综述"重新剔掉，故需 `_skip_page_screen` 豁免。**D14 把门整体摘掉后，这个"改表 → A4 不认"的陷阱在根上消失了**——这比打豁免补丁更干净。

### 2.5 与 `defer`（D8）的关系 —— 范围收缩

A3 现在**不需要 `defer`**：导出/回传本身就是"人工动作未完成"的天然表达。
`defer` / `pending_actions` 的用武之地**收缩到 A4**（非 OA 待补传 PDF）与 ④ 转出项。
**D8 仍要落地，但不再服务 A3**，只服务 A4 —— 落地面变小，风险同步变小。

### 2.6 A4 下载 = 100% 按清单直下（D14 · 已实施）

**决策原文**：*"A4 的下载直接按照提供的列表批量下载即可，不对类型重新判断和修改。"*

**口径**：A3 裁决表 = 权威清单。A4 只承担「下载 → 抽取」，**不再按类型（综述 / 指南 / 研究方案）重新筛掉人工已纳入的篇目**。类型信息降级为**标注**（`is_review` / `review_note`），仅供人工在 🔴 闸位参考，不再作为门。

#### 影响与收益

- **收益**：删掉"下门 + 豁免补丁"这一对互相纠缠的机制；A3 改成文件交接后，A4 再判类型本身就是**对人工裁决的二次推翻**，摘掉才是自洽的。
- **行为变化**：概览里 `excluded_review` 计数将归零；人工纳入的综述会**进到抽取**，多为 0 行 —— 但会带 `review_note` 软提示（"该文献疑似综述/meta，本就无原始 2×2 表，抽取为 0 属正常"），🔴 闸位看得见、可由人处置。
- **代价**：类型甄别原是**成本护栏**（避免为注定无 2×2 的文献花下载配额）。摘掉后下载量可能上升，属用户明确接受的取舍。

#### ⚠️ 同族但**未动**的第二处（需你另外拍板 = D15）

`pdf_extractor.extract()` **内置**的"强制类型甄别门（规律 R1）"会返回 `doc_info.excluded=True`，`block_a` 有两个消费点仍据此产出 `excluded_review`：

| 位置 | 场景 |
|---|---|
| `block_a.py:1426`（cached 分支） | 命中缓存 PDF 时按 PDF 内容类型排除 |
| `block_a.py:1017`（上传快速通道） | 「我已备好全文 PDF」上传后按 PDF 内容类型排除 |

这**不是"下载前"判断，而是"抽取层"判断**，且要改的是 `pdf_extractor` 本身。它的作用是把**综述正文转述的二手数据挡在合并之外**（防非原始数据入池）。是否也摘掉，涉及数据完整性，不按"下载"字样顺推——**待你决策**。
