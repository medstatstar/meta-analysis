|---|---|
| 1 | **A2 检索早就在 ct-literature 手里** —— 这不是"新增移交"，是既成事实。对话侧要简化的是**闸上展示量**，不是"谁检索"。 |

## 2. 关键证据（代码位）

### 2.1 A2 已在 ct-literature —— 但路径是坏的

- `adapters/block_a.py:271` `a2_build_tool_card(need_tool="ct-literature")`
- → `coze_client.execute_tool_cards()` 查表 → `adapters/tool_mapping_meta.json:5`
  ```json
  "cmd": ["C:/Anaconda3/python.exe", "{skill_dir}/scripts/ct_literature.py"]
  ```
- `_load_tool_mapping()`（`coze_client.py:1116`）**只对 `skill_dir` 做 expanduser / `__skillhub` 回退，不碰 `cmd`**
- 本机实测：`C:/Anaconda3/python.exe` **不存在**；`C:/Tools/Anaconda3/python.exe` 存在
- 后果链：`FileNotFoundError` → `except Exception`（`coze_client.py:1309`）吞掉 → `status:error`
  → `_extract_studies` 空 → `_read_literature_dir` 兜底读空 → **A2 静默 0 篇**（界面显示"合并总数 0"，不报错）

> 建议独立于 CCM 立即修（D13）。这条不修，后面所有"移交"都建在坏链路上。

### 2.2 A3 需要的判定，ct-literature 每次都已经算完

| 位置 | 事实 |
|---|---|
| `ct_literature.py:131` | `DEFAULT_PRISMA = True` —— **默认开** |
| `ct_literature.py:483` | `screen_prisma.screen(works, topic=…, review_type=…)` |
| `ct_literature.py:575 / 617` | 写 `.merged.json` 的 `prisma` 块 |
| `screen_prisma.py:164-169` | 每篇打 `prisma_stage` / `prisma_included` / `prisma_reason` |
| `screen_prisma.py:86 _passes_screen` | 规则：`type-not-required:<t>` ｜ `non-original-type:<t>` ｜ 主题相关性（topic token 未命中→剔除） |

而 meta-analysis 侧 A3 的 `is_likely_review()`（`block_a.py:432`，标题/摘要综述特征 + pubType）与 A3 review-guard 是**同一族规则**。**两份实现，其中一份的结果被丢弃。**

> 这是本次简化最大的杠杆：不是"再移交一件事"，而是"接上一条已经算好的线"。

### 2.3 A4 的"下载"其实是复合步骤

`block_a.py:1199 _a4_fetch_one` 的执行序：

```
① 下载前类型探测（:1216-1233）
   is_likely_review() + pdf_fetch.screen_page_type()
   命中 review/guideline → 不下载、不落盘、不抽取，返回 excluded_review
   （人工在 A3 翻纳入的篇目：_skip_page_screen=True，不受此门约束）
② _resolve_pdf_url() → pdf_fetch.download()  → 失败
③ _coze_pdf_download(doi) 服务端浏览器救援     → 失败
④ needs_upload（人工补传）
```

所以移交下载必须回答：**那层类型门跟着去哪？**

| 选项 | 内容 | 评价 |
|---|---|---|
| (a) 前移到 A2 | `--original-only` 源头排除 | 省检索配额，**更优**（不合格的根本不进来） |
| (b) 留在 A4 作第二网 | 保留 `screen_page_type` | 兜人工翻纳入的篇目，红线前置保护不丢 |
| **(a)+(b) 并存** | 源头排除 + 出口复检 | **建议**：源头省钱，二网保红线语义不动 |

## 3. 简化后的 A2 / A3 对话菜单

### A2（软停）—— 从 3 类展示压到「1 行 3 数」

v0.2 现状：覆盖总览 6 字段 + 各库条数 `dicttable` + 检索式 `textarea` + 未翻译残留 —— 全上屏。

```
② 检索 · 覆盖确认                〔软停 · 需你拍板〕
   42 篇 ｜ 状态 ok ｜ OpenAlex 28 · EuropePMC 14 · 预印本 2 ｜ 撤稿 1 ｜ 沉默漏检：无
   检索式：("osimertinib") AND ("NSCLC") AND (…)
   ── 你的选择
   [1] 批准 → 进 ③ 初筛
   [2] 改检索式（粘贴新式，重跑于 Phase 2 生效）
   [3] 看各库明细 / 未翻译残留 / 完整检索式   → /explain A2
   [4] 跳过本阶段（软停专属）
   [5] 打回 / 回退到更早阶段
```

改动：`dicttable` 各库条数压成一行；`untranslated` 仅非空时上屏；检索式默认截断显示。

### A3（软停）—— 从「全量逐条」变成「漏斗 + 边界项」

v0.2 现状：Top 5 + "共 42" + **强制文件交接**（因 N 常 > 10）。

```
③ 初筛 · 逐条裁决                〔软停 · 需你拍板〕
   漏斗：42 → 非原创类型 -3 → 主题无关 -25 → 纳入 14 ｜ 低置信 2
   （规则来源：ct-literature --prisma 确定性初筛，规则指纹 prisma@v<n>）
   ── 需你定夺（边界项 2 / 共 42）
   1. Chen 2024 · Lung Cancer · 主题词未命中   [低置信] ← 规则剔除，但标题强相关
   2. Park 2022 · Ann Oncol   · 摘要缺失       [低置信] ← 无摘要，规则无从判
   ── 你的选择
   [1] 批准放行 → 进 ④ 数据提取（🔴 红线，不可跳过）
   [2] 展开全部 42 条（⬇ 导出裁决表 / ⬆ 传回更新）
   [3] 改某条裁决（`改 S7 纳入`）
   [4] 打回规则（如这 3 篇综述确需保留 → 重跑 A2 带 --include-reviews）→ 回退 A2
   [5] 跳过本阶段（软停专属）
   [6] 打回 / 回退到更早阶段
```

**关键变化**：常规路径下，对话侧需人工定夺的条目数 = **边界项数**（通常个位数），而非全量 42 条
→ 落进 v0.2 D9 的 N≤10 阈值 → **A3 从"必须文件交接"降级为"多数情况对话内可完成"**，文件交接退为 `[2]` 逃生门。

## 5. 代价与风险（拍板前必须知道）

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| **R1** | **A2 变重、timeout 不够** | 前置下载让 A2 从"检索"变"检索+批量下载"；`a2_build_tool_card` timeout 写死 **120s** | 放宽 timeout + 走 `--progress` 流式（`execute_tool_cards` 已有 `on_line` 路径） |
| **R2** | **OA-only 硬边界** | ct-literature 只下合法 OA；非 OA 仍走 `needs_upload` | 正是 `pending_actions`（D8）的用武之地 → **D8 从"建议落地"升为"前置条件"** |
| **R3** | **规则初筛有偏倚** | ct-literature 明文"甄别异常一律放行"，放行 = 纳入 → 产生**假纳入** | 边界项必须真看，不能只看数；保留 `[2] 展开全部` 逃生门 |
| **R4** | **耦合面扩大** | meta → ct-literature 从 5 个 flag 扩到 9–10 个 | `tool_mapping_meta.json` 记录最低版本要求；CHANGELOG 交叉记录 |
| **R5** | **`prisma` 语义漂移** | 今天忽略、接上后 ct-literature 改规则会**静默改变 A3 结果** | 把规则指纹/版本写进 A3 菜单与审计日志 |
| **R6** | **A4 类型门丢失** | 移交下载时若顺手删掉 `_a4_fetch_one` 的探测段 → 红线前置保护消失 | `--original-only`(A2) + `screen_page_type`(A4) **双层并存**，写进 AC13 |
| **R7** | 委托失败无感 | A2 已经证明"失败会静默成 0 篇" | 菜单必须显式展示 `search_status`；非 ok 时打告警而非显示 0 |

## 8. 一句话总结

**不要问"A2/A3 能不能少做"，要问"哪一段判定放错了位置"。**
检索已在 ct-literature；初筛的规则它每次都已算完只等接上；下载可以搬过去，但搬的时候把类型门一起带上。
对话侧因此从"全量逐条"瘦身为"漏斗 + 边界项"——简化不是牺牲覆盖，是把人的注意力从 42 条收到 2 条。
