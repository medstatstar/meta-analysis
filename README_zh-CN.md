> **临床研究者友好的 R 语言 Meta 分析技能**
>
> 无需编程、无需记忆命令——在对话中用**自然语言**描述你的 Meta 分析需求，技能**自动完成**全套分析（合并计算、出图、报告）。底层基于 R 与 14 核心 + 2 可选专业 R 包（metafor、meta、netmeta、bayesmeta、dosresmeta、mada 等），输出语言随操作系统语言自动切换（中文系统出中文，否则出英文；可随时强制切换）。你提出需求后，技能**自动执行**分析并返回结果与图形；如需复现代码，可随时索要完整可复现 R 代码。

---

## 适用人群

meta-analysis 是 `ct-*` 临床试验技能家族的一员，主要面向三类人群：

- **各制药企业的临床试验从业者** —— 申办方、CRO，以及医学 / 统计 / 注册等角色，需要合并和比较研究证据；
- **在医疗机构中设计、管理临床试验项目，或参与临床试验研究实务的医护人员**；
- **希望系统学习循证医学与 Meta 分析方法的医学专业学生**。

## 1. 对话中使用（核心）

meta-analysis 是**对话式技能**：用自然语言告诉助手你要做什么——无需命令、无需记忆参数名。作为 WorkBuddy 技能，**自动加载、无需额外安装**。

以下 7 个真实对话示例。**示例 1 是上游「选题门控」（Topic Selection）**——在跑任何分析前先锁定候选方向；示例 2–7 从简单到高级排列。每个示例含 **「你说」** 和 **「助手回复（示意）」**，以及如何触发真实计算。

### 示例 1 · 选题：选择候选 Meta 分析方向（Topic Selection 上游门控）
**你说：**
> 我对 SGLT2 抑制剂在慢性肾脏病（CKD）中的肾保护与心血管获益感兴趣，但还没确定具体做哪个方向的 Meta，能帮我梳理候选方向吗？

**助手会这样回（示意）：**
> 好的，用「选题评估」框架（`references/topic-selection.md`）帮你锁定候选方向。这一步我先基于一手文献做**去重核查（R3 规则）**，再给候选——否则容易把"已被做透"的方向当成首选。
>
> **先划掉"已被做透"的方向**：泛化的「SGLT2i vs 安慰剂对 CKD 心肾复合终点」2024 年已被至少 5–6 篇大型 Meta 覆盖（如 BMJ Medicine 2024, 13 RCT/29 614 人；BMC Nephrol 2024 eGFR<60 亚组, 17 RCT/27 928 人；跨心血管代谢谱 Lancet 子刊 2024, 15 试验/100 952 人）。这些 Meta 还一致报告"糖尿病状态 / 基线 eGFR / UACR 无显著效应修饰"——常规亚组 Meta 的新意已被榨干，**不建议再做泛化配对 Meta**。
>
> 按"证据空白 + 新颖性"重新给 3 个候选（Stage 1 Gate 1：产出 1–3 个方向，不替你拍板）：
>
> **候选方向 ① 非糖尿病 CKD 的专属 Meta（最推荐）**
> - 干预：SGLT2i vs 安慰剂；人群：**非糖尿病 CKD**（剥离 DAPA-CKD / EMPA-KIDNEY 非糖尿病亚组 + 少量专门 RCT）
> - 四维初评：临床价值 5 / 可行性 4 / 数据可得性 4 / 新颖性 5 → 总分 18（强烈建议）
> - Meta 类型：标准 pairwise（meta / metafor）；IPD 最佳，发表亚组数据亦可
> - 依据：现有 Meta 几乎都把"糖尿病+非糖尿病"混报，原文自己点名"非糖尿病 CKD 证据仍不足、需更多研究"（Reyes-Farias PLOS ONE 2023）。
> - ⚠️ 非糖尿病亚组样本较小，需做把握度与异质性诚实讨论。
>
> **候选方向 ② SGLT2i 对 RAS 阻断剂（ACEi/ARB）持续使用的影响（机制桥接）**
> - 结局：RAS 停药 / 中断（CREDENCE + DAPA-CKD 联合分析已报降低 15%，PMID 37876229）
> - 四维初评：临床 4 / 可行性 3 / 数据 3 / 新颖性 5 → 总分 15（建议）
> - Meta 类型：标准 pairwise（HR 合并）；能提供该终点的 RCT 有限，需先核实 k 是否 ≥5
> - 价值：临床故事独特（"SGLT2i 让 RAS 用得住"），最不易撞车。
>
> **候选方向 ③ 晚期 CKD（eGFR<30 / CKD 4–5 期）疗效与安全性**
> - 结局：肾脏复合 + eGFR 斜率 + 罕见安全事件
> - 四维初评：临床 5 / 可行性 3 / 数据 3 / 新颖性 4 → 总分 15（建议）
> - Meta 类型：标准 pairwise；注意 2025 CJASN（Elenjickal, 10 RCT/4 800 例 eGFR<30）刚发，需找差异化角度
>
> **建议**：首选 ①（空白最实、临床需求最大、文献自证空白）；次选 ②（故事最独特）；③ 有 2025 新文阴影需先差异化。下一步可走 Full Assessment（PICO 分解 + 去重检索 + PRISMA/AMSTAR-2 预检）生成选题报告。

**📌 说明：** 当你「有方向但不确定具体做哪个 Meta」时，助手用选题框架产出 **1–3 个候选方向 + 四维评分 + Meta 类型**，而非替你拍板或只给一个答案。这是分析前的**上游门控（Topic Selection）**，不调用 R 计算。候选方向按**证据空白 / 新颖性**分层，且每项都带一手去重核查依据（R7 规则），避免把已饱和的泛化方向误推为首选。

### 示例 2 · 两组二分类 Meta（最常见）
**你说：**
> 合并以下 5 项二分类研究的 OR：
> 研究A: 实验组 30/100, 对照组 20/100
> 研究B: 实验组 45/120, 对照组 30/120
> ...

**助手回复（示意）：**
> ✅ 5 项研究，随机效应模型 (DL)，OR = 1.52 (95%CI: 1.18–1.96), I² = 34%
> （可随时索要完整可复现 R 代码。）

**📌 自动执行：** 你描述需求后，助手**自动执行**分析并返回真实数字；如需复现代码，说 **「给我完整 R 代码」**。

### 示例 3 · 效应量转换
**你说：**
> 把 Cohen's d = 0.8 转成 logOR

**助手回复（示意）：**
> ✅ d = 0.8 → logOR ≈ 1.45 (SE ≈ 0.38)，基于公式 logOR = d × π/√3

### 示例 4 · 异质性 + 亚组
**你说：**
> 我做了 8 项研究的连续型 Meta，SMD 合并，但 I² 比较高，想按地区做亚组

**助手回复（示意）：**
> ✅ 8 项研究，SMD = 0.42 (95%CI: 0.15–0.69), I² = 78%
> 亚组分析（地区）：
> - 亚洲 (k=4): SMD = 0.55, I² = 45%
> - 欧美 (k=4): SMD = 0.28, I² = 62%
> - 组间 Q = 4.12, p = 0.04

### 示例 5 · Complex：网络 Meta 含多个决策（弹出路由菜单）
**你说：**
> 我想做个网络 Meta，有 4 种干预措施，但还没决定用频率学派还是贝叶斯，也不知道要不要做剂量反应

**助手回复（示意）：**
> 4 种干预已明确。还有 2 个关键选择，我来帮你理清：
>
> **① 你倾向哪种分析框架？**
> - (a) 频率学派 — `netmeta`，基于倒方差法，适合一致性网络
> - (b) 贝叶斯 — `gemtc` (JAGS) / `multinma` (Stan) **仅本地**（coze 端为已知环境限制：容器无 root 无法装 JAGS，云端请用 (a) netmeta）；`bayesmeta` 支持贝叶斯配对比较（本地可用）
>
> **② 要不要纳入剂量反应？**
> - (a) 不做 — 纯两两比较网络
> - (b) 做 — 需要剂量-效应参数，贝叶斯框架更合适
>
> **③ 还拿不准？** → 说「详细解释这些选择之间的差异」，我先讲清临床与统计含义再让你决定

**📌 说明：** 当你已点名能力但卡在「哪个选项 / 设计族」时，助手**弹出能力路由菜单**逐步确认，而非替你拍板或甩全量菜单。菜单含统一「解释差异」入口（见本文 §5）——拿不准时先讲清再决定。

### 示例 6 · Vague：不确定用哪种模型（grill-me）
**你说：**
> 我想做个 Meta 分析，但不确定该用哪种模型，能帮我梳理一下吗？

**助手回复（示意）：**
> 好的，我们先把你的需求理清楚。每轮问 1–3 个聚焦问题，每个带推荐默认：
>
> **第 1 轮（3 题）：**
> 1. 你的结局类型是？— 二分类(OR/RR) / 连续型(SMD/MD) / 生存(HR) / 单组率 / 其他
> 2. 数据是两组比较还是多组网络？— 两组 / 多组网络 / 不确定
> 3. 有没有特殊的依赖结构？— 多臂研究 / 多结局 / 个体数据(IPD) / 都没有
>
> （回答后继续追问，直到锁定模型 — 不会甩全量菜单）

**📌 说明：** 当你说「不确定用哪种」时，助手用 **grill-me 逐分支追问** 理清需求，而非甩全量菜单或替你选。

## 3. 首次使用 FAQ

**Q: 我只给了效应量和研究数量，其他参数没给——能算吗？**
A: 可以。大多数分析只需 3 项——效应量（或率/HR）+ α + 把握度。省略部分（双侧 α=0.05、1:1 随机、随访）会用合理默认值填充；若确实缺少必要参数，助手会追问。

**Q: 结果里的 n 是每组还是总样本量？**
A: 默认是**每组**；配对/交叉设计报告每序列，生存分析常报告所需总事件数。输出会明确标注，不会混淆。

**Q: 我描述需求后，会立即算出结果吗？**
A: 是的。你提出需求后，助手**自动执行**分析并返回真实数字与图形——无需额外的触发词。计算在云端 coze R 引擎完成（数据披露见第 5 节）。

**Q: 想要可复现的 R 代码用于投稿或稽查，怎么要？**
A: 说 **"给我完整 R 代码"**。每次分析都会返回可复现的 R 代码（含 R 版本与包版本），你可以自行复制、修改、重跑。

**Q: 中文系统下输出是中文吗？**
A: 是的。默认输出语言随 OS 语言设定——中文系统出中文，否则出英文。此默认行为仅影响显示语言、无需额外授权；可随时通过提示词强制切换（如「用中文回复」/「switch to English」）。

**Q: 数据格式不对怎么办？**
A: 说 **"帮我把 SPSS/Excel 数据转成 CSV"**，助手会推荐安装 `@skill:statdata-transfer` 做 50+ 格式转换。

**Q: 如果数据要保密怎么办？**
A: 可以用**模拟/占位数据**跑通整个分析流程，然后要求技能输出**完整可复现 R 代码**，自行在本地用真实数据运行这段代码即可。技能本身只把**分析参数 / 汇总统计量**（事件数、样本量、效应量等）发送至云端 coze R 引擎——**从不接触您的原始数据集或个体级数据**（除非您显式选择通过云端做 IPD 分析，此时 IPD 是否上云由您决定）。

**Q: 发现结果有误怎么办？怎么上报？**
A: 本技能遵循错误报告流程。若您怀疑结果有误（或引擎报错），直接说 **"上报问题" / "report a bug" / "提交错误报告"**。技能在检测到疑似缺陷时（如引擎报错、重试仍失败）也会**主动询问**是否上报——**每会话最多 1 次**，您可随时拒绝。无论哪种方式，助手都会：
1. **生成一份脱敏报告**（11 键白名单：skill / skill_version / test / error_type / error_code / engine_status / description / locale / query_origin / session_hash / attempts——**不含您的原始输入值或个人数据**，仅 `description` 字段由您把关披露，如所用算法/函数、错误消息原文）；
2. **展示报告全文供您检视**——可补充问题描述或更正任何内容后再确认；
3. **经您明确确认后发送**——本会话有 coze 调用则发往统一端点 `https://ct-bugreport.coze.site/run`；纯本地则**保存脱敏报告到本地并给出作者联系方式**，由您自行决定是否邮件联系作者（技能本身不代发，数据不出域，除非您主动发送）；
4. **收到回执**——包括您此前从同一来源提交的报告是否已被修复（含修复说明）或仍在处理中。

整个过程您完全可控：报告在**发送前**先展示给您，未经您明确说「发送」绝不传输任何内容。

## 4. 执行机制

- **自动执行：** 你描述分析需求后，技能**自动完成分析**并返回真实数字与图形——无需额外的触发词或确认。计算默认在云端 coze R 引擎完成。
- **默认计算路径：** 本技能将分析请求发送到云端 coze R 引擎（`https://ct-meta.coze.site/run`）执行（数据披露见第 5 节）。
- **可复现代码：** 每次分析返回可复现 R 代码（含 R 版本与包版本），说 **「给我完整 R 代码」** 即可获取，用于投稿或稽查。
- **出站授权：** 默认端点已预置白名单、自动执行；若使用自定义端点（`COZE_META_ENDPOINT`），首次会弹确认提示（见第 5 节）。
- **输出结果仅供参考**，投稿或申报前请结合专业背景复核。

## 5. 数据与隐私说明

技能在**两种**情况下会向外部发送数据：① 你提出分析需求时，技能**自动发送**分析请求执行；② 你确认发送错误报告时，发送脱敏报告。两种都**不发送个人身份信息**。

**5.1 分析请求（云计算）**
- 发送内容：您的**分析数据**——研究事件数 / 样本量 / 效应量等**汇总统计量**，不含任何个人身份信息，发送前经脱敏处理。
- 发送时机：您提出分析需求后，技能**自动发送**至云端执行；**每会话首次出站前**，技能会向您口头披露一次发送内容与端点（随后自动执行，不逐次确认）。
- 端点：默认 `https://ct-meta.coze.site/run`（已预置 `adapters/config.json` 的 `auto_approve_endpoints` 白名单）。自定义端点（`COZE_META_ENDPOINT`）首次使用会弹确认提示（AUTH-BLOCK），确认后写入白名单、后续免确认。
- 拒绝：若您不同意发送，技能返回"本次未使用云端分析"的明确提示。

**5.2 随请求发送的元数据**
每次请求还会附带两条元数据（**分析请求与错误报告均含**）：
- `query_origin`：本机主机名的 SHA-256 哈希，仅用于服务端归因 / 限流，**非明文主机名**；
- `locale`：OS 语言，用于双语输出。

两者均不用于识别您的个人身份。

**5.3 错误报告**
- 发送内容：**仅** 11 键白名单信封（skill / skill_version / test / error_type / error_code / engine_status / description / locale / query_origin / session_hash / attempts），**不含任何分析数据与个人身份信息**。`description` 是唯一自由文本字段，且您在确认前会审阅（硬边界：不含可识别个人 / 机构 / 受试者信息）。
- 端点：统一错误报告端点 `https://ct-bugreport.coze.site/run`。
- 拒绝：若您拒绝，什么都不发送；若本次会话无云端调用，报告改为本地保存（`save_local_report`，数据不出本机）。

> **一句话总结**：你的**分析汇总数据**在你提出需求后**自动**发往云端执行（每会话首次出站前披露一次）；**错误报告**仅在你确认后发往统一端点；两条元数据（`query_origin` 哈希 + `locale`）为匿名归因用。原始数据与个体记录永不离开本机。
