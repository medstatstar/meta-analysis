> **临床研究者友好的 R 语言 Meta 分析技能**
>
> 无需编程、无需记忆命令——在对话中用**自然语言**描述你的 Meta 分析需求，技能**自动完成**全套分析（合并计算、出图、报告）。底层基于 R 与 14 核心 + 2 可选专业 R 包（metafor、meta、netmeta、bayesmeta、dosresmeta、mada 等），输出语言随操作系统语言自动切换（中文系统出中文，否则出英文；可随时强制切换）。你提出需求后，技能**自动执行**分析并返回结果与图形；如需复现代码，可随时索要完整可复现 R 代码。

---

## 适用人群

meta-analysis 属于 `ct-*` 临床试验技能家族，主要面向三类人群：

- **各制药企业的临床试验从业者** —— 申办方、CRO，以及医学 / 统计 / 注册等角色，需要合并与比较研究证据；
- **在医疗机构中设计、开展或参与临床研究的医生与护士**，需要 Meta 分析 / 系统评价支持；
- **希望系统学习循证医学与 Meta 分析方法学的医学专业学生**。

## 1. 能做什么——场景索引

**系统评价流程**（上游门控）排最前，其余按**分析目的**分组。每行给典型临床场景 + 可直接抄写的自然语言。同一分析可能从多个入口到达。

> 底层 R 包名（metafor / meta / netmeta …）见第 6 节「进阶参考」；普通用户无需关心。

> **📌 与工作台五大模块对应（2026-10-27 对齐）**：本索引分类与已发布工作台（`https://meta.medstatstar.com`）同源——**选题评估**（对话态走案例 6 / 选题框架）、**文献准备**（检索 / 初筛 / PDF 下载 / 数据提取，工作台专属，对话态不提供）、**Meta 分析**（下表 ①–⑤ 全部走云端 coze R 引擎）、**样本估算**、**论文撰写**（当前不提供）。
>
> **⛔ 论文撰写当前不提供**：初稿撰写 / AI 评审 / 参考核验 / 投稿前 QA 均不可用，请勿在对话或工作台中寻求该功能。
>
> **⛔ 无引擎支持的条目已移除**：ROBINS-I、RoB 交通灯图（plot）、不一致性热图、AI 辅助文献筛选、图形数字化、缺失值插补——这些在 R 引擎中**不存在对应 task**（调用会返回 `unknown_task`），对话态不得承诺或尝试调用。文献检索 / 筛选 / PDF 下载请使用工作台「文献准备」模块。RoB 2.0 / RoB 1.0 仅作叙述性评估（不含交通灯图）。

## 2. 使用案例大全（对话中使用 · 核心）

meta-analysis 是**对话式技能**：用自然语言告诉助手你要做什么——无需命令、无需记忆参数名。作为 WorkBuddy 技能，**自动加载、无需额外安装**。

下面按**难度分级**（★ 基础 / ★★ 进阶 / ★★★ 专业）给出 16 个真实案例，与 §1 场景索引对应。每个案例含 **「你这样说」**、**「助手会这样回（示意）」** 和 **「🖥️ 网页工作台」** 三段；示意数字为真实计算口径示例（随机效应 REML / DL 等），实际值随你的数据而定。

> **计算默认走云端 coze R 引擎**（出站披露见第 5 节）。**对话态不提供**文献检索 / 初筛 / PDF 下载 / 数据提取（请用工作台「文献准备」模块）与论文撰写（当前不提供）。

## ★ 基础用法

### 案例 1 · 两组二分类 Meta（最常见）

**你这样说：**

> 合并以下 5 项二分类研究的 OR：  
> 研究A: 实验组 30/100, 对照组 20/100  
> 研究B: 实验组 45/120, 对照组 30/120  
> 研究C: 实验组 25/90, 对照组 18/85  
> 研究D: 实验组 40/110, 对照组 28/105  
> 研究E: 实验组 35/95, 对照组 22/92

**助手会这样回（示意）：**

> ✅ 5 项研究，随机效应模型（REML），OR = 1.52（95%CI: 1.18–1.96），I² = 34%。  
> 已生成森林图（含汇总菱形与 I² 标注）。（可随时说「给我完整 R 代码」取可复现代码。）

**🖥️ 工作台：**

> 进入「Meta 分析」模块 → 上传 CSV（列名 `study / ai / bi / ci / di`，或粘贴四格表）→ 效应量选「OR」→ 点「启动流程」（无数据可点「演示数据」跑通整条链路）。

### 案例 2 · 连续型 Meta + 亚组（异质性）

**你这样说：**

> 我做了 8 项研究的连续型 Meta，SMD 合并，但 I² 比较高，想按地区做亚组。

**助手会这样回（示意）：**

> ✅ 8 项研究，SMD = 0.42（95%CI: 0.15–0.69），I² = 78%。  
> 亚组分析（地区）：
>
> - 亚洲（k=4）：SMD = 0.55，I² = 45%
> - 欧美（k=4）：SMD = 0.28，I² = 62%
> - 组间 Q = 4.12，p = 0.04

**🖥️ 工作台：**

> 「Meta 分析」模块当前只做**基础合并**：上传数据（mean / sd / n 两组）→ 选「连续型 / SMD」→ 点「运行」，输出合并效应与森林图。**该模块不含亚组分析入口**（没有「亚组变量」填列框）。要做亚组拆分，请在对话态直接说「按地区做亚组分析」——由云端引擎按 subgroup 维度计算，工作台暂不提供该交互。

### 案例 3 · 效应量转换（d → logOR）

**你这样说：**

> 把 Cohen's d = 0.8 转成 logOR。

**助手会这样回（示意）：**

> ✅ d = 0.8 → logOR ≈ 1.45（SE ≈ 0.38），基于公式 logOR = d × π/√3。

**🖥️ 工作台：**

> 工作台**暂不提供**效应量换算工具。这类轻量换算直接在**对话态**说「把 d 转成 logOR」即可实时得出（含 SE）。

### 案例 4 · 可视化（森林图，指定主题）

**你这样说：**

> 画森林图，lancet 主题。

**助手会这样回（示意）：**

> ✅ 森林图已生成（Lancet 主题，含汇总菱形与 I² 标注）。[SVG 输出，内联于单文件 HTML 报告]

**🖥️ 工作台：**

> 任意合并分析后，「Meta 分析」结果区会**自动给出森林图**（含汇总菱形与 I² 标注）；但**不支持指定主题 / 风格**（lancet / jama / nejm / bmj 等）。需要特定期刊主题或漏斗图增强，请在对话态说「画森林图，lancet 主题」。

### 案例 5 · 预计算效应量直接合并（yi + CI → 森林图）

**你这样说：**

> 我有 5 个研究现成的效应量和置信区间，直接合并画森林图：OR 与 95%CI 分别是 1.52[1.18,1.96]、1.31[1.02,1.69]、1.88[1.40,2.53]、1.47[1.13,1.91]、1.66[1.29,2.14]。

**助手会这样回（示意）：**

> ✅ 5 项研究，随机效应（REML），合并 OR = 1.57（95%CI: 1.33–1.85），I² = 32%。已生成森林图（含汇总菱形与 I² 标注）。  
> （可随时说「给我完整 R 代码」取可复现代码。）

**🖥️ 工作台：**

> 「Meta 分析」模块支持**预计算数据**上传：列名用 `study / te / sete`（te=效应量对数、sete=标准误），或给 `te / ci_low / ci_high` 由系统折算 SE → 选对应效应量 → 点「启动流程」，结果区自动给森林图。这是对「原始四格表」之外的另一主流输入方式。

## ★★ 进阶用法

### 案例 6 · 选题评估（上游门控，真实去重探针）

**你这样说：**

## 3. 首次使用 FAQ


**Q: 我只给了效应量和研究数量，其他参数没给——能算吗？**
A: 可以。合并类分析只需**每研究的效应数据**（二分类 ai/bi/ci/di、连续 mean/sd/n，或预计算 te/seTE）；未指明的选项用合理默认值补齐（随机效应 REML/DL、双侧 α=0.05、1:1 分组等），若缺少**必要**参数（如两组连续型缺 mean 或 sd），助手会先追问再计算。

**Q: 结果里的 n 是每组还是总样本量？**
A: 默认是**每组**；配对/交叉设计报告每序列，生存分析常报告所需总事件数。输出会明确标注，不会混淆。

**Q: 我描述需求后，会立即算出结果吗？**
A: 是的。你提出需求后，助手**自动执行**分析并返回真实数字与图形——无需额外的触发词。计算在云端 coze R 引擎完成（数据披露见第 5 节）。

**Q: 想要可复现的 R 代码用于投稿或稽查，怎么要？**
A: 说 **"给我完整 R 代码"**。每次分析都会返回可复现的 R 代码（含 R 版本与包版本），你可以自行复制、修改、重跑。

**Q: 中文系统下输出是中文吗？**
A: 是的。默认输出语言随 OS 语言设定——中文系统出中文，否则出英文。此默认行为仅影响显示语言、无需额外授权；可随时通过提示词强制切换（如「用中文回复」/「switch to English」）。

**Q: 数据格式不对怎么办？**
A: 说 **"帮我把 SPSS/Excel 数据转成 CSV"**，助手会推荐安装 `@skill:statdata-transfer` 做 50+ 格式转换。

**Q: 如果数据要保密怎么办？**
A: 可以用**模拟/占位数据**跑通整个分析流程，然后要求技能输出**完整可复现 R 代码**，自行在本地用真实数据运行这段代码即可。技能本身只把**分析参数 / 汇总统计量**（事件数、样本量、效应量等）发送至云端 coze R 引擎——**从不接触您的原始数据集或个体级数据**（除非您显式选择通过云端做 IPD 分析，此时 IPD 是否上云由您决定）。

**Q: 发现结果有误怎么办？怎么上报？**
A: 本技能遵循错误报告流程。若您怀疑结果有误（或引擎报错），直接说 **"上报问题" / "report a bug" / "提交错误报告"**。技能在检测到疑似缺陷时（如引擎报错、重试仍失败）也会**主动询问**是否上报——**每会话最多 1 次**，您可随时拒绝。无论哪种方式，助手都会：
1. **生成一份脱敏报告**（11 键白名单：skill / skill_version / test / error_type / error_code / engine_status / description / locale / query_origin / session_hash / attempts——**不含您的原始输入值或个人数据**，仅 `description` 字段由您把关披露，如所用算法/函数、错误消息原文）；
2. **展示报告全文供您检视**——可补充问题描述或更正任何内容后再确认；
3. **经您明确确认后发送**——本会话有 coze 调用则发往统一端点 `https://ct-bugreport.coze.site/run`；纯本地则**保存脱敏报告到本地并给出作者联系方式**，由您自行决定是否邮件联系作者（技能本身不代发，数据不出域，除非您主动发送）；
4. **收到回执**——包括您此前从同一来源提交的报告是否已被修复（含修复说明）或仍在处理中。

整个过程您完全可控：报告在**发送前**先展示给您，未经您明确说「发送」绝不传输任何内容。

**Q: 我在工作台（网页）里看到报错，怎么处理？**
A: 工作台侧如遇异常，结果区会直接给出明确的错误原因与「重试」入口，可按提示重试或调整输入。若怀疑**分析结果有误**或属于引擎逻辑问题，请在对话态说「上报问题」（见上条）——错误上报为对话态能力，工作台不提供上报入口。

## 5. 数据与隐私说明

技能在**两种**情况下会向外部发送数据：① 你提出分析需求时，技能**自动发送**分析请求执行；② 你确认发送错误报告时，发送脱敏报告。两种都**不发送个人身份信息**。

**5.1 分析请求（云计算）**
- 发送内容：您的**分析数据**——研究事件数 / 样本量 / 效应量等**汇总统计量**，不含任何个人身份信息，发送前经脱敏处理。
- 发送时机：您提出分析需求后，技能**自动发送**至云端执行；**每会话首次出站前**，技能会向您口头披露一次发送内容与端点（随后自动执行，不逐次确认）。
- 端点：默认 `https://ct-meta.coze.site/run`（已预置 `adapters/config.json` 的 `auto_approve_endpoints` 白名单）。自定义端点（`COZE_META_ENDPOINT`）首次使用会弹确认提示（AUTH-BLOCK），确认后写入白名单、后续免确认。
- 拒绝：若您不同意发送，技能返回"本次未使用云端分析"的明确提示。

**5.2 随请求发送的元数据**
每次请求还会附带两条元数据（**分析请求与错误报告均含**）：
- `query_origin`：本机主机名的 SHA-256 哈希，仅用于服务端归因 / 限流，**非明文主机名**；
- `locale`：OS 语言，用于双语输出。

两者均不用于识别您的个人身份。

**5.3 错误报告**
- 发送内容：**仅** 11 键白名单信封（skill / skill_version / test / error_type / error_code / engine_status / description / locale / query_origin / session_hash / attempts），**不含任何分析数据与个人身份信息**。`description` 是唯一自由文本字段，且您在确认前会审阅（硬边界：不含可识别个人 / 机构 / 受试者信息）。
- 端点：统一错误报告端点 `https://ct-bugreport.coze.site/run`。
- 拒绝：若您拒绝，什么都不发送；若本次会话无云端调用，报告改为本地保存（`save_local_report`，数据不出本机）。

> **一句话总结**：你的**分析汇总数据**在你提出需求后**自动**发往云端执行（每会话首次出站前披露一次）；**错误报告**仅在你确认后发往统一端点；两条元数据（`query_origin` 哈希 + `locale`）为匿名归因用。原始数据与个体记录永不离开本机。
